# Demo deployment

Use a source checkout with Python 3.12. Install `requirements-demo.txt` for hosting. The tested environment is Streamlit 1.66.0 and Pydantic 2.14.1.

Public server command (Railway/Procfile already select this mode):

```sh
python -m pipeline.launch --mode demo --port=$PORT --address=0.0.0.0
```

For Streamlit Community Cloud, use `pipeline/adapters/primary/app.py` as the main file and set `PIPELINE_MODE=demo` in the process environment before startup. Public config defaults to `config/demo_sales_rep.json` (the in-app selector also offers `config/demo_b2b_services.json`); `PIPELINE_INSTANCE_CONFIG` may point to another validated public JSON file. A missing or invalid configuration shows a safe error message.

CORS and XSRF protection are enabled; Streamlit usage telemetry is disabled. Verify reverse-proxy and websocket configuration on the intended host.

The public adapter is stored only in `st.session_state`, never a process cache. Every visitor receives a fresh copy of the synthetic seed (92 Sales Rep prospects, 33 B2B Services deals), with relative dates resolved against the visitor's own calendar date. Seed fixtures are generated by `tools/build_demo_fixtures.py`; regenerate them there rather than editing the JSON by hand. Changing the instance config fingerprint clears cached adapters, data, and widgets. Browser disconnection retention follows Streamlit settings; do not promise durable edits across expiry, restart, or deployment. Account intelligence is read from the synthetic `intel.json.example` file. There is no email or SMS execution, external enrichment, LLM call, or persistent write in demo mode. The Call and Email buttons open sandbox dialogs that only log an activity to the session.

Before publication: run `.venv/Scripts/python.exe tools/run_tests.py`; inspect both workspaces in separate browser sessions; confirm the public process has the intended mode. Automated AppTest tests cover mutations, all navigation, and session isolation.
